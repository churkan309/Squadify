SQUADIFY - PROJECT NOTE
=======================

เอกสารนี้อธิบายโครงสร้างและการทำงานของโปรเจกต์ Squadify ตามโค้ดปัจจุบัน
ใช้เป็นเอกสารสำหรับทำความเข้าใจโปรเจกต์ แก้ไขโค้ด และพัฒนาฟีเจอร์ต่อ


1. ภาพรวมโปรเจกต์
------------------

Squadify เป็นแอป Flutter สำหรับหาและจัดการกลุ่มเล่นเกม (Squad/Party)
ผู้ใช้สามารถทำงานหลักได้ดังนี้:

- สมัครสมาชิกและเข้าสู่ระบบด้วย Email/Password ผ่าน Firebase Authentication
- สร้าง Squad ของตัวเอง โดยเลือกเกม จำนวนสมาชิก และคำอธิบาย
- ดู Squad ที่เปิดรับสมาชิก
- เข้าร่วม Squad หรือออกจาก Squad
- ดูสมาชิกใน Squad และจัดการสมาชิกในกรณีที่เป็นหัวปาร์ตี้
- พูดคุยใน Community ของ Party ที่ผู้ใช้อยู่
- สร้างโพสต์และคอมเมนท์ โดยบันทึก username ของผู้เขียน
- ดู Profile และออกจากระบบ

เทคโนโลยีหลัก:

- Flutter/Dart: UI และ application logic
- Provider: dependency injection และ state management
- Firebase Authentication: ผู้ใช้และ session การเข้าสู่ระบบ
- Cloud Firestore: ฐานข้อมูลผู้ใช้ Party สมาชิก โพสต์ และคอมเมนท์
- SharedPreferences: เก็บ draft ข้อความ Community ในเครื่อง
- Firebase Core: initialize Firebase ในแอป

3. จุดเริ่มต้นแอปและ Dependency Injection
-------------------------------------------

ไฟล์: lib/main.dart

ลำดับการเริ่มแอป:

1. เรียก WidgetsFlutterBinding.ensureInitialized()
2. เรียก Firebase.initializeApp() ด้วย DefaultFirebaseOptions
3. สร้าง MultiProvider
4. เริ่ม MyApp
5. StartupPage ฟัง FirebaseAuth.authStateChanges()
6. ถ้ามีผู้ใช้ ให้ไป MainNavigationPage
7. ถ้าไม่มีผู้ใช้ ให้ไป LoginPage

Provider ที่ลงทะเบียน:

- Provider<PartyProvider>
	ใช้สำหรับอ่านและแก้ไขข้อมูล Party/สมาชิก

- Provider<CommunityProvider>
	ใช้สำหรับอ่านและเขียนโพสต์/คอมเมนท์ Community

- ChangeNotifierProvider<AuthProvider>
	ใช้เก็บผู้ใช้ปัจจุบัน username และแจ้ง UI เมื่อ auth state เปลี่ยน

ตัวแปรสำคัญใน main.dart:

- DefaultFirebaseOptions.currentPlatform
	configuration ของ Firebase สำหรับ platform ที่กำลังรัน
- FirebaseAuth.instance.authStateChanges()
	stream ที่แจ้งว่ามีการ login/logout หรือไม่
- MaterialApp.title
	ชื่อแอปสำหรับ metadata ไม่ใช่ข้อความ AppBar ที่แสดงบนหน้าจอ


4. Model และตัวแปรข้อมูล
-------------------------

ไฟล์: lib/models/party_model.dart

4.1 SquadMember

แทนสมาชิกหนึ่งคนใน parties/{partyId}/members/{uid}

- uid: String
	Firebase Auth UID ของสมาชิก ใช้เป็น document ID ด้วย
- name: String
	ชื่อที่บันทึกตอนสร้างหรือเข้าร่วม Party
- avatarUrl: String
	URL รูป avatar ปัจจุบันยังมีค่าเริ่มต้นเป็นค่าว่าง
- isLeader: bool
	true เมื่อเป็นหัวปาร์ตี้
- joinedAt: DateTime?
	เวลาที่เข้าร่วม Party

factory SquadMember.fromFirestore()
อ่านข้อมูลจาก Firestore document และใช้ค่าเริ่มต้นเมื่อ field ไม่มี

4.2 Party

แทน Squad หนึ่งกลุ่มใน collection parties

- id: String
	document ID ของ Party
- game: String
	ชื่อเกม เช่น Valorant หรือ League of Legends
- iconPath: String
	path ของ icon เกมใน assets
- maxMembers: int
	จำนวนสมาชิกสูงสุดของเกมนั้น
- description: String
	คำอธิบาย Party แก้ได้โดย host
- hostId: String
	UID ของหัวปาร์ตี้
- hostName: String
	ชื่อหัวปาร์ตี้ที่บันทึกไว้ใน Party
- memberCount: int
	จำนวนสมาชิกที่เก็บเป็น counter ใน document Party
- status: String
	สถานะ เช่น open, full, closed
- createdAt: DateTime?
	เวลาสร้าง Party

factory Party.fromFirestore()
แปลง Firestore document เป็น Dart model


5. Authentication และ Profile
------------------------------

ไฟล์: lib/services/auth_service.dart

AuthService เป็นชั้นที่คุยกับ Firebase Auth และ users collection

ตัวแปรสำคัญ:

- _auth: FirebaseAuth
	dependency สำหรับ login/register/logout
- _firestore: FirebaseFirestore
	dependency สำหรับอ่านและเขียน users/{uid}

เมธอดหลัก:

- currentUser
	คืน Firebase User ปัจจุบัน
- authStateChanges()
	คืน stream ของสถานะ login
- signIn(email, password)
	login ด้วย Email/Password และแปลง error เป็น AuthException
- signUp(email, password, username)
	สร้าง Firebase user, ตั้ง displayName และสร้าง profile ใน Firestore
- signOut()
	logout
- getUserProfile(uid)
	อ่าน users/{uid}

ไฟล์: lib/providers/auth_provider.dart

AuthProvider เป็น ChangeNotifier ที่ครอบ AuthService เพื่อให้ widget ฟังการเปลี่ยนแปลง

ตัวแปรสำคัญ:

- _authService: AuthService
	service ที่ใช้โหลด auth/profile
- _authSubscription: StreamSubscription<User?>?
	subscription ของ authStateChanges และถูก cancel ใน dispose()
- _user: User?
	Firebase user ปัจจุบัน
- _username: String?
	username ที่โหลดจาก Firestore หรือ displayName เป็น fallback
- _disposed: bool
	ป้องกัน async callback เรียก notifyListeners หลัง provider ถูกทำลาย

เมธอดสำคัญ:

- username
	getter สำหรับ UI
- currentUsername()
	อ่าน username จาก users/{uid} แบบ async และ fallback เป็น displayName/ผู้เล่น
- _onUserChanged()
	อัปเดต user เมื่อ login/logout
- _loadUsername()
	โหลด username จาก Firestore และตรวจ UID/dispose ก่อนอัปเดต
- dispose()
	ยกเลิก auth subscription

โครงสร้าง profile ที่ใช้:

users/{uid}
	uid: String
	username: String
	email: String
	avatarUrl: String
	createdAt: Timestamp

7. PartyProvider และการทำงานของ Squad
--------------------------------------

ไฟล์: lib/providers/party_provider.dart

ตัวแปรภายใน:

- _firestore: FirebaseFirestore
	database หลัก
- _auth: FirebaseAuth
	ใช้หา UID ผู้ใช้ปัจจุบัน
- _parties
	getter ที่ชี้ไป collection parties
- _uid
	getter UID ปัจจุบัน ถ้าไม่ได้ login จะเป็น null

Streams สำหรับอ่านข้อมูล:

- allOpenParties
	Party ที่ status == open เรียง createdAt ล่าสุดก่อน
- myHostedParty
	Party ที่ hostId ตรงกับ UID ผู้ใช้
- myCurrentParty
	ใช้ collectionGroup('members') หา Party ที่ผู้ใช้อยู่
- partyById(id)
	ฟัง Party document เดียว
- membersOf(partyId)
	ฟัง members subcollection และเรียง joinedAt

คำสั่งหลัก:

- createParty()
	ตรวจว่า user ยังไม่มี Party จากนั้น batch เขียน Party และสมาชิก host
- hasHostedParty()
	เช็กว่าผู้ใช้เป็น host อยู่แล้วหรือไม่
- isMemberOfAnyParty()
	เช็กว่าผู้ใช้อยู่ใน Party ใดหรือไม่
- joinParty()
	ใช้ transaction ตรวจ Party, สมาชิกซ้ำ, จำนวนสมาชิก และเพิ่ม memberCount
- leaveParty()
	ใช้ transaction ลบสมาชิกและลด memberCount
- updateDescription()
	อนุญาตเฉพาะ host ที่ตรงกับ hostId
- removeMember()
	host ลบสมาชิกคนอื่นออกและลด memberCount
- deleteParty()
	ตรวจ host แล้วลบ members และ Party ด้วย batch

กติกาใน application logic:

- ผู้ใช้หนึ่งคนไม่ควรเป็น host หลาย Party
- host ไม่สามารถ join Party อื่น
- host ไม่สามารถ leave Party ตัวเอง ต้องลบ Party
- เข้าร่วมไม่ได้เมื่อ memberCount ถึง maxMembers
- เมื่อเต็มจะเปลี่ยน status เป็น full

หมายเหตุ: กติกาเหล่านี้อยู่ใน client/provider เป็นหลัก ปัจจุบัน workspace ไม่มี
firestore.rules จึงควรเพิ่ม Security Rules ฝั่ง Firebase เพื่อบังคับสิทธิ์จริง

-----------------

หน้าจะแสดงข้อมูล Party, จำนวนสมาชิก, รายชื่อสมาชิก และปุ่มตามสิทธิ์ผู้ใช้

12. ฐานข้อมูลและการจัดเก็บข้อมูล
---------------------------------

ระบบใช้ Cloud Firestore เป็น NoSQL document database
ข้อมูลไม่ได้เก็บเป็นตาราง/row แบบ SQL แต่เป็น collection/document/subcollection

Collections ปัจจุบัน:

1. users
	 users/{uid}
	 profile ของผู้ใช้

2. parties
	 parties/{partyId}
	 ข้อมูล Party

	 parties/{partyId}/members/{uid}
	 สมาชิกของ Party

3. posts
	 posts/{postId}
	 กระทู้ Community โดยมี partyId เป็นตัวเชื่อมกับ Party

	 posts/{postId}/comments/{commentId}
	 คอมเมนท์ของกระทู้

Local storage:

- SharedPreferences key: community_draft
- ใช้เก็บข้อความ draft ที่ผู้ใช้พิมพ์ค้างไว้
- ชื่อไฟล์ firestore_service.dart เป็นชื่อเดิม แต่ service นี้ไม่ได้คุย Firestore

Timestamp:

- ตอนเขียนใช้ FieldValue.serverTimestamp()
- ตอนอ่านแปลงเป็น DateTime?
- ค่า server timestamp อาจเป็น null ชั่วคราวก่อน Firestore ประมวลผล

17. Flow การทำงานหลัก
----------------------

17.1 เปิดแอป

main()
	-> initialize Firebase
	-> สร้าง Provider
	-> StartupPage
	-> authStateChanges()
	-> MainNavigationPage หรือ LoginPage

17.2 สมัครสมาชิก

RegisterPage
	-> validate form
	-> AuthService.signUp()
	-> Firebase createUserWithEmailAndPassword
	-> updateDisplayName
	-> set users/{uid}
	-> เปิด MainNavigationPage

17.3 Login

LoginPage
	-> validate form
	-> AuthService.signIn()
	-> Firebase auth state เปลี่ยน
	-> AuthProvider โหลด username
	-> MainNavigationPage

17.4 สร้าง Party

MainNavigationPage กด FAB
	-> ตรวจ hasHostedParty()
	-> ตรวจ isMemberOfAnyParty()
	-> CreatePartyDialog
	-> PartyProvider.createParty()
	-> batch เขียน parties/{id} และ members/{uid}
	-> กลับไป Squad detail

17.5 Join Party

Home PartyCard
	-> SquadDetailPage
	-> กด Join
	-> PartyProvider.joinParty()
	-> transaction ตรวจจำนวน/สมาชิกซ้ำ
	-> เพิ่ม member และ update memberCount/status

17.6 Community

กด tab Community
	-> อ่าน myCurrentParty
	-> ถ้ามี Party สร้าง CommunityPage(partyId)
	-> query posts ที่ partyId ตรงกัน
	-> เพิ่ม post/comment พร้อม authorId และ authorName

17.7 Logout

SettingsPage
	-> AuthService.signOut()
	-> authStateChanges เป็น null
	-> กลับ LoginPage


18. ข้อควรระวังและสิ่งที่ควรพัฒนาต่อ
--------------------------------------

1. Firestore Security Rules
	 ยังไม่พบ firestore.rules ใน workspace การกันสิทธิ์ Community/Party ใน UI
	 ไม่เพียงพอสำหรับความปลอดภัยจริง ควรตั้ง rules ให้ตรวจ request.auth.uid
	 และ membership ของ Party ฝั่ง Firebase

2. Race condition ของการสร้าง/เข้าร่วม Party
	 การตรวจ hasHostedParty และ isMemberOfAnyParty ก่อนสร้างอยู่ใน client
	 ถ้ามีหลายเครื่องทำพร้อมกันอาจเกิดการแข่งกันเขียน ควรใช้ rules หรือ backend authority

3. สมาชิกหน้า Members
	 members_page.dart ปัจจุบันใช้ข้อมูลตัวอย่างแบบ hard-coded ไม่ได้อ่าน membersOf()
	 ถ้าต้องการใช้งานจริงควรผูกกับ PartyProvider และ Party ปัจจุบัน

4. Draft ใช้ key เดียว
	 community_draft เป็น draft กลาง ถ้าเปลี่ยน Party อาจเห็น draft จาก Party เดิม
	 ควรเปลี่ยน key เป็น community_draft_{partyId} หากต้องการแยกตาม Party

5. Legacy posts
	 โพสต์เก่าที่ไม่มี partyId จะไม่ปรากฏใน postsForParty()
	 ต้อง migrate ข้อมูลเก่าหรือยอมรับว่าเป็นโพสต์จาก schema รุ่นก่อน

6. Error handling ของ async actions
	 การเพิ่มคอมเมนท์, save draft, join/leave/delete ควรมี loading state และแสดง error
	 ให้สม่ำเสมอ รวมถึงป้องกันการกดปุ่มซ้ำ

7. Profile query
	 ProfilePage อ่าน Firestore ใน build() หาก rebuild บ่อยอาจอ่านซ้ำ
	 ควรย้าย future ไป initState หรือรวม profile ไว้ใน AuthProvider

8. Tests
	 ปัจจุบันไม่มีโฟลเดอร์ test และ flutter test จึงยังรันไม่ได้
	 ควรเพิ่ม unit test สำหรับ validators/providers และ widget test สำหรับ navigation/dialog

9. ชื่อ package
	 pubspec.yaml ยังใช้ name: flutter_application_1 ซึ่งเป็นชื่อจาก template
	 ควรเปลี่ยนเป็นชื่อ package ที่สื่อถึง Squadify หากมีแผน publish/deploy จริง

20. สรุปสั้น
------------

Squadify แบ่งหน้าที่เป็นชั้นค่อนข้างชัดเจน:

- pages รับผิดชอบ UI และ user interaction
- providers รับผิดชอบ state และการคุยกับ database
- services ห่อ Firebase/local storage
- models แปลง Firestore data เป็น object ที่ใช้ใน Dart
- widgets รวม UI ที่ใช้ซ้ำ
- data/theme/validation เก็บค่ากลางของระบบ

ฐานข้อมูลหลักคือ Cloud Firestore ส่วน Firebase Auth จัดการตัวตนผู้ใช้ และ
SharedPreferences ใช้เก็บ draft ในเครื่องเท่านั้น การทำงานแบบ realtime หลักมาจาก
Firestore snapshots() และ StreamBuilder/AsyncStreamSection ในหน้า UI
